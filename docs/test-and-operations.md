# 首版本测试与运维要求

## 1. 必测流程

- Client 首次注册、重复注册、凭据撤销和重新注册。
- Server 重启后 Client 自动重连并发送完整快照。
- Client 网络断开、Server 重启和网络恢复。
- 串口首次发现、热插拔、设备占用、读写失败和超时。
- 同一串口并发指令互斥。
- 过期指令、重复指令、权限不足和设备离线。
- 更新下载失败、Hash 错误、签名错误、启动失败和自动回滚。
- Linux 开机后 Client 自动启动和异常退出自动拉起。

## 2. 测试层级

- 单元测试：状态机、协议解析、参数校验、更新清单校验。
- 集成测试：Server、WebSocket、Fake Serial Adapter 和 systemd 模拟器。
- Client 测试：断线重连、快照生成、热插拔和更新流程。
- 端到端测试：Web 发起操作，经 Server 到 Client，再返回结果。
- 浏览器测试：加载中、恢复中、空状态、离线、错误和更新进度。

仓库中的 `npm test` 会先执行 TypeScript 构建，再运行全部 Node 测试。目前测试覆盖：

- 协议 Envelope 和 payload 校验、串口 AT 参数校验。
- Client 同一设备互斥、不同设备并发和锁释放。
- Server 与协议 Client 的同步、指令结果、断线、重连和状态查询。
- 实际 Client 进程的身份文件持久化、首次注册和重启重连。
- HTTPS/WSS 健康检查，以及 Client 认证关闭/开启两种握手模式。
- Updater 的 Hash/签名前置校验、平台/架构/最低协议版本、自检失败和健康检查失败回滚。
- Test Box 的硬件特征聚合、控制口/日志口绑定和日志事件边界校验。

真实串口设备不可用时，必须使用可控的 Fake Serial Adapter，不得跳过串口测试。

## 3. 首版本运维边界

- Server 为单实例，内存状态丢失属于已知行为。
- Server 日志输出结构化 JSON，交由 systemd/journald 或部署平台保留。
- 更新包通过签名制品目录或制品仓库发布。
- 必须提供配置项说明、TLS 证书注入、Client 安装、升级、回滚和故障排查文档。
- 需要在文档中明确：无数据库版本不提供跨 Server 重启的历史操作查询。
